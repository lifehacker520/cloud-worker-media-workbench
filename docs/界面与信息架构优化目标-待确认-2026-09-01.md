# 云员工媒体工作台｜整体页面与交互重制目标

> 本文件是 v2 待确认目标。它把本轮真实体验发现的问题和负责人希望得到的结果整理成可执行、可验收的产品合同；确认前不修改产品代码、数据、账号、权限、Git 发布状态，也不把本文件写成已完成结果。

## 0. 一句话结果

把客户端从“多个空页面和管理卡片的集合”，重制成一个普通用户能看懂、能完成工作、能知道下一步的云员工媒体工作台：

```text
选择云员工
→ 进入该岗位的工作流
→ 查看待处理任务和平台信号
→ 执行或等待 AI 处理
→ 人工审核/确认
→ 交付、发布准备或复盘
```

本轮最优先解决的是产品骨架和交互可靠性，不是增加更多功能数量。

## 1. 本轮结果合同

### 1.1 目标使用者

- 内容运营人员：每天查看账号新作品、整理参考内容、创建内容任务；
- 负责人/管理员：查看整体状态、配置成员和连接器、处理异常；
- 客户成员：使用被授权的云员工能力，不能看到管理后台配置。

### 1.2 用户打开客户端后应能回答

1. 我现在在哪个云员工或工具里？
2. 今天有什么新内容或待处理事项？
3. 哪些事情已经完成，哪些需要我判断？
4. 点击后会发生什么，成功/失败/处理中分别是什么状态？
5. 下一步结果会进入哪里？

### 1.3 不可接受的结果

- 侧边栏把云员工、工具、规划中页面和管理员入口混在同一层；
- 点击左侧设置项目后，右侧仍展示所有设置内容，选择和内容没有一一对应；
- 普通用户在设置页看到客户、品牌、成员、连接器授权、邀请、目录同步或备份管理；
- 页面只有大块白色空容器，没有明确下一步；
- 用户滚动到页面底部后看到无意义的巨大空白、内容穿透或平台状态栏挤占工作区；
- 按钮没有加载、完成、失败、重试、取消、权限不足等状态；
- 作品标题看起来可点击，但实际只能打开账号主页，或没有说明直链不可用；
- 工程测试通过就被当作用户体验通过。

## 2. 真实用户体验审计

本轮使用 Computer Use 连续检查客户端导航、设置、滚动、监控、内容编辑、发布、数据洞察、AI 工作区和反馈协作页面。未执行新增账号、删除账号、刷新采集、外部链接跳转、提交反馈、创建内容任务或修改设置等有副作用操作。

### 已观察到的事实

| 编号 | 事实 | 结论 |
|---|---|---|
| A1 | 左侧同时放置总览、监控中心、内容中心、发布中心、数据洞察、AI 工作区、反馈与协作、设置与更新 | 导航层级没有表达“云员工/工具/管理”的关系 |
| A2 | 设置页选择“客户端更新”或“服务连接”后，三个设置内容仍全部显示；左侧选中态更像滚动定位而不是单页切换 | 设置页违反了用户要求的“左侧项目—右侧对应内容”一一对应 |
| A3 | 设置页向下滚动后依次出现客户与品牌上下文、成员目录、项目成员、连接器权限、成员邀请、目录同步、备份校验 | 普通设置与管理员后台混在同一页面，且形成很长的管理表单页 |
| A4 | 设置页管理卡片包含多处水平滚动表格；管理员区域继续使用大量英文眉题 | 信息密度、角色边界和可读性都不适合普通用户 |
| A5 | 内容编辑页有创建任务表单、右侧空任务区和底部空状态；滚到底部后出现较大空白区域 | 空状态没有围绕下一步收束，页面像未完成的模板 |
| A6 | 发布、数据洞察、AI 工作区均显示重复的顶部标题/正文标题、英文眉题和大块空状态 | 未来页面占据了真实工作区，却没有形成可操作路径 |
| A7 | 小红书、抖音、视频号平台接入状态固定出现在左侧底部 | 平台状态没有放在真正需要使用的平台工具或连接设置中，长期挤占导航 |
| A8 | 监控页能显示账号头像、作品数量、未读提醒和选中账号的作品流；但样本中的历史作品标题不是可聚焦链接，旁边的链接是“打开账号主页” | 监控展示部分已存在，但作品级打开和键盘可用性仍未形成一致契约 |
| A9 | 通过键盘导航可以进入设置、监控、内容、发布、洞察、AI 和反馈页面；Computer Use 某些鼠标点击曾出现原生交互管道关闭，随后重新读取状态后页面未改变 | 这是本轮工具环境的交互异常，不能直接判定为产品点击 bug；后续仍需同时做鼠标、键盘和视觉验收 |

证据位置：当前项目 `public/index.html`、`public/app.js`、`public/styles.css`、`public/workspace-admin.js`，以及本轮 Computer Use 读取的 Electron 无障碍树和页面截图。

## 3. 信息架构：把“云员工”和“工具”分开

### 3.1 推荐的左侧结构

```text
云员工媒体工作台
├─ 工作台（原总览，可暂保留“总览”名称）
├─ 云员工
│  ├─ 内容编辑云员工       P0，可用
│  ├─ 账号运营云员工       规划
│  ├─ 私域跟单云员工       规划
│  ├─ 客户成功客服云员工   规划
│  ├─ GEO 专员云员工       规划
│  ├─ 直播运营云员工       规划
│  └─ 电话销售云员工       规划
├─ 工具中心 ▾
│  └─ 监控中心
├─ 反馈与协作
└─ 设置
```

### 3.2 七类云员工卡片

本轮界面按现有七类业务名单展示 7 张卡片：内容编辑、账号运营、私域跟单、客户成功客服、GEO 专员、直播运营、电话销售。只有内容编辑云员工进入 P0 可用状态，其他卡片可以进入规划占位页，但必须显示真实状态，不能伪装成已经实现。

当前项目 `GOAL.md` 的底层产品架构另有“8 岗”口径（7 类岗位 + 平面设计）。本轮只调整界面展示，不删除或改写底层 8 岗架构；平面设计在界面中的最终位置需要负责人确认。

### 3.3 一级导航迁移规则

- “内容中心”改为“内容编辑”或“内容编辑云员工”，作为云员工工作区，不再作为杂项中心；
- “发布中心、数据洞察、AI 工作区”从一级导航移除；其能力分别进入内容编辑工作流的发布准备、数据反馈/复盘和 AI 辅助节点；
- “监控中心”从一级导航移入“工具中心”二级菜单；工具中心未来可容纳平台检测、下载、素材采集等工具；
- 保留旧路由和数据兼容一段时间，旧链接进入对应新入口或显示迁移提示，不因隐藏菜单删除代码和数据；
- 左侧底部不再固定显示“小红书、抖音、视频号”平台接入卡片；平台状态放到工具中心/监控中心和设置中的服务连接；
- 反馈与协作保留为用户反馈入口；管理员观察区单独放入管理员视图；
- 工作台首页只展示待处理事项、未读监控、失败任务和下一步，不再用“中台模块地图”占据主要空间。

## 4. 全局页面系统

### 4.1 页面骨架

每个页面只允许一套页面标题层级：

```text
页面标题
用途说明                         主要动作
──────────────────────────────────
当前工作内容
```

具体要求：

- 删除普通用户不需要的英文眉题，例如 `MONITOR CENTER`、`LATEST WORKS`、`SETTINGS & RELEASES`；
- 删除顶部标题和正文标题重复渲染；
- 不把 `P0`、`草稿`、`规划`放在导航主视觉位置；开发状态放到卡片辅助信息；
- 全局顶部只保留当前页面标题、运行状态、必要的全局动作；
- 页面滚动区域统一，侧边栏固定，主内容区域有明确的滚动容器和底部留白；
- 页面底部不再出现与当前任务无关的平台接入栏；
- 统一主按钮、次按钮、危险按钮、状态徽标、提示、确认弹窗和 Toast 的视觉规则；
- 主要操作必须有键盘焦点、可读名称和禁用原因。

### 4.2 滚动和空状态

用户说的“往下滑一下就滑到底，下面没有任何东西挡着”，本质上不是要阻止用户滚动，而是要修正页面容器和内容收束：

- 长页面只能在主内容区滚动，不让正文穿透到错误容器；
- 页面底部保留合理的结束间距，不出现无限空白；
- 空状态使用紧凑高度，明确说明“为什么为空”和唯一下一步；
- 表单未完成时，不要在右侧和底部同时放两个巨大空白容器；
- 任务处理中显示进度/阶段，失败显示原因和重试，不用空白代替状态；
- 在 1440、1280、1024、860 和窄窗口下检查垂直滚动、横向溢出、固定栏和底部操作可见性。

## 5. 设置与更新：重新定义为“真正的设置页”

### 5.1 目标布局

参考负责人提供的截图，只采用这一条核心模式：

```text
设置
├─ 左侧：设置分类/具体项目
└─ 右侧：当前选中项目唯一对应的设置内容
```

左侧选择“客户端更新”，右侧只显示客户端更新；选择“服务连接”，右侧只显示服务连接。不能再把三个设置卡片全部纵向放在右侧，再用滚动定位模拟切换。

### 5.2 普通用户设置目录

建议先提供以下足够但不过度的项目：

| 分组 | 设置项目 | 右侧内容 |
|---|---|---|
| 基础 | 通用 | 启动页、语言、主题/明暗、界面密度、通知偏好 |
| 工作台 | 云员工工作区 | 默认进入的云员工、工作台首页显示哪些待办、工作流提示 |
| 内容 | 内容编辑 | 默认素材目录、默认平台、审核提示、草稿保存说明 |
| 监控 | 监控偏好 | 自动刷新频率、未读提醒、失败提醒、浏览器补采提示 |
| 连接 | 服务连接 | 本地服务状态、数据位置、平台会话状态、连接失败处理 |
| 更新 | 客户端更新 | 当前版本、检查更新、版本说明、下载/安装/重启状态 |
| 帮助 | 关于与反馈 | 版本信息、诊断信息入口、提交反馈和使用说明 |

这些项目先建立清楚的界面和状态；没有真实能力的设置必须标为“暂未接入”，不能放一个看起来能用但不产生效果的控件。

### 5.3 管理员专属区域

以下内容从普通设置页移出，单独建立“管理员设置/管理后台”，通过角色权限控制：

- 客户与品牌上下文；
- 成员目录、项目成员和角色；
- 连接器权限、Token/会话授权状态；
- 成员邀请、组织目录同步；
- 数据备份、校验和恢复；
- 审计日志和系统诊断。

管理员后台也采用左侧项目—右侧内容结构，不再把所有管理表单堆成一个超长页面。普通客户成员既看不到入口，也不能通过旧路由直接看到管理内容。

### 5.4 更新交互状态

“检查更新”必须是一条真实状态机：

```text
可检查
→ 检查中
→ 已是最新
或 发现新版本
→ 用户确认下载
→ 下载中
→ 下载完成
→ 用户确认重启安装
→ 安装成功/失败及恢复办法
```

网页/开发模式必须明确显示“当前为网页/开发模式，请下载桌面客户端”，不能让用户误以为提交 GitHub 代码后网页会自动更新。

## 6. 监控中心：作为工具中心的核心工具

### 6.1 监控页工作流

```text
工具中心
→ 监控中心
→ 加入/筛选账号
→ 查看账号头像、平台、状态和未读
→ 点击账号查看作品
→ 最新作品在最上方
→ 点击作品标题打开作品直链
→ 查看后清除未读
```

### 6.2 必须保留和修复的交互

- 账号列表显示真实头像；没有头像时显示首字占位；
- 账号名称、平台、分组、作品数、采集状态和操作按钮有稳定列结构；长名称可换行，不遮挡操作；
- 账号列表和作品流之间使用真正可拖拽的分隔条，并设置最小/最大宽度；
- 选择账号后，右侧只显示该账号作品和发布时间；
- 最新作品严格按真实发布时间倒序；
- 作品标题本身是可聚焦链接，优先使用作品级 `work.link`；
- 没有作品直链时，明确显示“作品直链不可用，打开账号主页”，不能把主页伪装成作品链接；
- 新作品显示红色未读提醒；进入账号详情后标记该账号新作品为已读，红色提醒消失；
- 删除账号必须二次确认，并清楚说明是否同时删除本地已采集作品；
- 小红书、抖音、视频号分别显示已获取、需浏览器补采、需登录/验证、失败、暂无作品等真实状态；
- 平台适配失败时保留原因、重试或补采入口，不显示假成功。

## 7. 内容编辑云员工及未来能力收纳

内容编辑云员工是当前 P0 主工作区，页面要围绕“从素材到可审核内容包”组织：

```text
业务目标/客户与品牌资料
→ 素材
→ 选题/脚本
→ 编辑/平台适配
→ 人工审核
→ 发布准备
→ 发布后数据
→ 复盘与知识沉淀
```

- “发布中心”不再成为孤立一级页面，而是内容任务中的发布准备节点；
- “数据洞察”不再成为空的一级看板，而是发布后的数据反馈与复盘节点；
- “AI 工作区”不再成为空的一级入口，而是贯穿检索、整理、生成、分析的能力层；
- 内容任务页面必须区分未创建、编辑中、处理中、待审核、已通过、已退回、发布准备、失败和已归档；
- 没有任务时只保留一个创建任务入口；创建任务后，右侧展示任务步骤和当前下一步，不再出现多个无意义大空白区；
- 外部平台发布继续保留授权、人工确认和失败恢复边界。

## 8. 全局交互状态规范

所有可操作功能至少定义以下状态：

| 状态 | 用户看到什么 | 用户能做什么 |
|---|---|---|
| 初始/空 | 说明当前没有数据及原因 | 执行唯一主要动作 |
| 加载中 | 明确对象和进度，不只转圈 | 取消（可行时）或等待 |
| 成功 | 显示结果、时间和下一步 | 查看、继续或撤销（可行时） |
| 失败 | 显示具体原因和影响 | 重试、补采、修正或转人工 |
| 权限不足 | 说明需要什么权限、谁可处理 | 返回或申请权限 |
| 未保存 | 标出未保存变更 | 保存、放弃或继续编辑 |
| 危险操作 | 说明影响和恢复方式 | 取消或二次确认 |
| 已完成/已读 | 显示状态已改变 | 可回看历史记录 |

全局还要统一处理：

- 页面切换后滚动位置回到顶部；
- 返回、取消、关闭弹窗行为一致；
- 异步按钮防止重复提交；
- 成功/失败消息不遮挡主要内容；
- 鼠标、键盘和窄窗口都能完成核心路径；
- 不用无意义的闪烁、漂浮和英文装饰替代状态说明。

## 9. 分阶段执行范围（确认后才开始）

### P0｜工作台壳层和设置页

- 完成云员工 7 卡片和工具中心折叠导航；
- 去除一级发布/洞察/AI 入口，保留兼容路由；
- 删除全局平台接入底栏；
- 全局页面只保留一套中文标题；
- 重做设置页左侧目录—右侧唯一内容；
- 普通用户设置和管理员后台分离；
- 完成更新检查状态显示；
- 完成主滚动容器、空状态和底部收束。

### P1｜监控和内容工作流体验

- 监控中心迁入工具中心；
- 修复头像、作品直链、作品标题键盘链接、未读和账号详情；
- 修复可拖拽分栏、账号长名称、封面和状态布局；
- 内容编辑页收纳发布准备、数据反馈和 AI 能力节点；
- 补齐加载、失败、重试、权限和确认状态。

### P2｜后续平台和岗位能力
