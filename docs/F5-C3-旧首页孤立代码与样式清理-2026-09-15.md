## 4. 为什么确认可以删除

### 4.1 判定依据（逐层收窄）

| 层 | 检查内容 | 结果 |
|---|---|---|
| L1 | 13 个前端可执行文件（`public/**/*.js`、`public/**/*.html`、`electron/**/*.{mjs,js,cjs}`）中是否出现目标类 | **105 + 26 个类全部无使用者** |
| L2 | 是否存在动态拼接（`'content-' + x` 这类扫描盲区） | 无。旧 CW 已重写，其余文件不用 `content-*` 类 |
| L3 | 含目标类的**复合选择器**（如 `.content-node-panel .panel-heading .eyebrow`）是否也恒不匹配 | 是，`.content-node-panel` 无 DOM → 整条选择器恒不匹配 → 可删 |
| L4 | 被牵连删除的**非目标类**是否仍被前端使用 | 15 个彻底消失的类（`is-human` `is-succeeded` `status-*` 等）**前端零使用** |
| L5 | 被其他页面复用的类是否因此失去样式 | 4 个类（`is-empty` `is-warning` `phase-label` `section-intro`）在剥离后**在新 CSS 中仍有定义** |

**L4/L5 是本次最关键的安全检查。** 结果：**危险项 0 个**。

### 4.2 脚本层保护

`/tmp/f5c3-strip-css.py` 内置 4 道闸门：

1. **拒绝名单**：文件名含 `digital-human-workspace.css` 直接退出码 3
2. **括号平衡校验**：`{` 与 `}` 数量不等则拒绝写入
3. **体积校验**：结果比原文更大则拒绝写入（防止误改）
4. **默认 dry-run**：必须显式 `--write`

### 4.3 一个差点踩中的坑（记录备查）

`digital-human-workspace.css` 里有 15 个类（`dh-badge-done` `dh-tone-amber` `dh-tone-indigo` 等）在字符串扫描中显示"**无使用者**"。

**但它们全是活代码** —— DH 里用的是动态拼接：

```js
'<span class="dh-badge dh-badge-' + meta.tone + '">'
'<article class="dh-summary-card dh-tone-' + card.tone + '">'
```

**字符串级扫描对动态拼接完全无效。** 若按扫描结果删除，会静默破坏新中心的徽章与配色。因此该文件**整文件排除**，不进清理脚本。
