## 4. 产品规则不明确点（按任务第 12 条停止，不自行猜测）

### Q1（阻塞 G3）：P05 的字幕、Logo、片头片尾、画幅配置，应该在哪里做？

**冲突事实**：
- 你的任务要求："P05：视频模板、背景、字幕、Logo、片头片尾和画幅"
- 新中心自己的设计声明："本切片只做选择与状态显示，不做登记与训练"
- 实际状态：新中心 P05 只有模板**选择**；模板版本的**登记**在旧页（`POST /api/content/template-versions`）

**两种互斥的解读**：
- (a) 新中心 P05 应新增模板配置表单（字幕开关、Logo 位、片头片尾、画幅），保存为新的 template version
- (b) 模板配置仍由模板登记处负责，新中心 P05 只做选择 —— 那么 P05 的检查项应按"选择"验收，而非"配置"

**影响**：选 (a) 需新增一套表单与后端字段；选 (b) 则 P05 无缺口。**执行方式差别很大，请明确。**

### Q2（阻塞 G2）：P07「需修改后重新生成」是否等于现有的「重试」？

**冲突事实**：
- 新中心「重试本条」的 disabled 提示是"只有**失败或被退回**的明细可以重试" —— 暗示"需修改"可走重试
- 但 nextAction 文案表另有 `regenerate_item` = "修改输入后重新生成"，且无对应动作
- 旧页有独立的 `applyRevision`（CE-21 应用修改并生成新版本），语义是"改内容后产生新版本"

**两种互斥的解读**：
- (a) 重试即重新生成，无需新增（则只需清理 `regenerate_*` 这段**无动作的文案**，避免提示用户去做不可做的事）
- (b) 需要独立的"改输入后重新生成"，且要保留旧版本（则需新增动作，并明确版本策略）

**同时需明确**：任务要求"旧版本是否保留"。这需要产品给出结论，因为它决定服务端 attempt 模型是否要变。

### Q3（阻塞 G4）：B11 监控作品带入链路，终点应指向哪里？

**冲突事实**：
- F5-C0 判定 B1「创建内容任务」为 P0 阻塞，但因**归属存疑**未列入可迁移项 —— 创建内容任务是"内容编辑"的职责，而数字人口播中心的定位是"用已确认文案生产口播视频"
- 若 B1 不迁入新中心，则监控中心的 `content-work-prefill` 事件**不应**改指向新中心

**需要你明确**：数字人口播中心是否要承接「创建内容任务」？这决定 G4 是否执行。

### Q4：P04 的"绑定员工"是否必要？

任务要求"视频是否能绑定员工、文案和目标声音"。当前映射表结构是 `video + script + voiceSource + template`，**无员工字段**，且后端 `video_mappings` 表也无 `profile_id` 列。

**两种解读**：(a) 模式 B 是"已有视频口型同步"，原视频里已有真人，"绑定员工"概念不适用，不需要；(b) 需要记录该视频属于哪个员工档案。

**注**：这一项若要 (b)，将需要**改数据库结构**（新增列），而任务明确禁止——因此我判断它更可能是 (a)。**但仍需你确认，不自行决定。**

## 附 A：并行通道改动的疑似缺陷（仅记录，未修改）

```js
// public/digital-human-workspace.js（当前工作区版本）
if (page === DH_PAGE_ASSETS && dhAssets.status !== 'ready') {
  dhLoadAssets();
dhLoadCapability();        // ← 缩进缺失，且被置于 if 块内
}
```

两个问题：
1. **缩进错误**，提示该处可能处于编辑中间态
2. **逻辑问题**：`dhLoadCapability()` 被放进 `if (dhAssets.status !== 'ready')` 内，因此只有当资产尚未加载时才会触发能力探测。第二次进入 P03（`dhAssets.status === 'ready'`）时不会刷新能力状态 —— 与函数名表达的"检测真实能力"意图不符

`dhLoadCapability()` 自身逻辑是完整的（try/catch/FINALLY 式状态回填），问题仅在调用点。

**建议由该改动的作者处理**，本任务不越界修改。
